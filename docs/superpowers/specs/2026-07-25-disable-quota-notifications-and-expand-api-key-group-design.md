# 取消额度不足通知并加宽 API 密钥分组设计

## 背景

当前钱包余额或订阅额度低于阈值时，结算流程会异步调用通知服务。通知服务根据用户设置选择邮件、Webhook、Bark 或 Gotify。此前为避免低余额邮件重复发送，还在 `users.setting` JSON 中保存了 `quota_warning_email_sent` 内部状态，并在充值、兑换、签到等余额增加路径中重置该状态。

API 密钥管理表格当前同时显示“分组”和“创建时间”。分组列宽为 220px，紧凑型分组按钮还要容纳倍率徽标和展开图标，较长分组名会被截断；创建时间列占用 180px。

## 目标

1. 完全停止钱包余额和订阅额度不足通知，包括邮件、Webhook、Bark 和 Gotify。
2. 保留注册验证、密码重置、上游模型更新等其他通知。
3. 删除仅服务于低余额邮件单次提醒的状态与恢复逻辑，不增加数据库迁移。
4. API 密钥管理表默认隐藏“创建时间”，将释放的宽度用于分组按钮。
5. 展开分组菜单后能够完整读取较长的分组名称。

## 非目标

- 不删除用户通知渠道配置，也不改变其他通知类型的分发规则。
- 不删除或迁移数据库中已经存在的 `quota_warning_email_sent` JSON 键。
- 不改变 API 密钥的分组更新接口、权限或计费逻辑。
- 不改变移动端 API 密钥卡片布局。

## 后端设计

### 从结算源头停止额度通知

- 删除钱包结算和订阅结算完成后的额度通知调用。
- 删除 `checkAndSendQuotaNotify`、`checkAndSendSubscriptionQuotaNotify`、`sendWalletQuotaNotify` 及其专用函数类型。
- `PostConsumeQuota` 不再接收仅用于触发额度通知的布尔参数，并同步更新所有调用方。

这样可以避免创建无效后台任务、构造无用通知内容或占用通知限流计数。

### 增加集中防护

`NotifyUser` 在执行通知限流和渠道选择前检查通知类型。遇到 `quota_exceed` 时直接返回成功，不向任何渠道分发。

这层防护覆盖旧调用、遗漏调用和未来误调用，保证“额度不足通知已禁用”成为通知服务的稳定行为，而不只依赖当前结算调用链。

### 清理旧邮件状态

- 删除 `model/user_setting_state.go` 和对应测试。
- 删除充值、兑换、签到、返利划转审批、批量额度更新等路径中的邮件状态恢复调用。
- 将 `UpdateUserSetting` 恢复为直接保存公开的 `dto.UserSetting`，不再为内部邮件状态加锁和合并 JSON。

数据库中已有的 `quota_warning_email_sent` 键不会影响读取；用户下次保存通知设置时，该废弃键会随正常 JSON 重写自然消失。无需跨 SQLite、MySQL、PostgreSQL 的数据库迁移。

## 前端设计

### 默认列可见性

在 API 密钥表的初始列可见性中加入：

```ts
created_time: false
```

“创建时间”仍保留在列选择器中，用户可以手动重新显示。已有的显式列偏好继续优先于默认值。

### 分组列和菜单

- 分组列宽从 220px 增加到 400px，正好使用默认隐藏创建时间后释放的 180px。
- 紧凑按钮继续保持单行和现有行高，避免整张表变高。
- 展开菜单宽度继续跟随按钮宽度。
- 菜单选项中的分组名称和描述允许换行，不再使用单行截断，确保超长名称也能完整读取。

该调整只改变 API 密钥管理桌面表格的展示，不修改分组数据或更新行为。

## 错误处理与兼容性

- 禁用额度通知是正常行为，直接返回成功，不记录错误日志。
- 其他通知类型仍走现有通知限流、目标校验和发送错误处理。
- 旧 `users.setting` JSON 继续兼容；不执行批量数据清理，也不引入数据库方言差异。
- 旧浏览器保存的显式列可见性设置继续生效；没有显式设置的用户采用新的默认值。

## 测试与验证

### 后端

- 先增加失败回归测试，证明 `NotifyUser` 对 `quota_exceed` 的邮件、Webhook、Bark、Gotify 均不进行分发。
- 确认额度通知在限流检查前被跳过。
- 删除只验证旧低余额邮件状态和重复提醒行为的测试。
- 运行 `go test ./model ./service -count=1`，并检查所有 `PostConsumeQuota` 调用方成功编译。

### 前端

- 运行现有前端测试、类型检查、涉及文件 Lint、格式检查和生产构建。
- 在桌面浏览器验证“创建时间”默认隐藏、分组列宽约为 400px、分组菜单宽度跟随按钮。
- 使用长分组名验证展开菜单无文本裁切或重叠。
- 在移动视口确认 API 密钥卡片布局未受影响。

## 验收标准

1. 钱包和订阅额度低于阈值时，不发送任何渠道的额度不足通知。
2. 注册验证、密码重置和其他非 `quota_exceed` 通知行为保持不变。
3. 结算后不再创建额度通知后台任务，也不再读写低余额邮件状态。
4. API 密钥管理页首次使用新默认配置时不显示“创建时间”。
5. 分组按钮获得原创建时间列的宽度，展开后长分组名可完整读取。
6. 用户仍可通过列选择器显示“创建时间”。
